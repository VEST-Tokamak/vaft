# NICE adapter

> **Experimental.** No VEST reference slice reconstructs yet: 0 of 34 in the
> issue #666 study (see `validation/nice_issue_666/README.md`). Nothing in the
> routine pipeline calls this adapter, and no production default depends on it.

This adapter prepares the standalone NICE `nice_recon` text-file interface
directly from canonical ODS data. It does not translate an EFIT k-file or reuse
TokaMaker geometry.

```python
from vaft.code.nice import (
    NiceConfig, prepare_nice_inputs, run_nice, vest_reference_parameter_file,
)

config = NiceConfig(
    shot=41672,
    time=0.331,
    workdir="nice-41672-331ms",
    nice_home="/path/to/nice",
    source_revision="7ad1ea8f3da4fee25a61a7c2c01b1773db5f4906",
    parameter_file=vest_reference_parameter_file(),
)
inputs = prepare_nice_inputs(ods, config)
result = run_nice(inputs, config)
```

`prepare_nice_inputs` and `collect_nice_outputs` do not import NICE and are
suitable for CI. `run_nice` is the only function that requires the executable.

The per-case `nice_case_manifest.json` records the source revision, COCOS
mapping, exact enabled and disabled diagnostic table, geometry hash, native
input hashes, and the fixed passive-current vector/hash. By default, the exact
axisymmetric Green-function response of those fixed currents is subtracted
from every magnetic diagnostic before fitting. This is the fixed-external-
source formulation, avoids NICE's 100-coil limit for VEST's 950 passive
filaments, and never exposes passive currents as reconstruction unknowns.
`external_coils` remains available for small machines and controlled tests.

NICE's text backend writes native equilibrium tables. The collector converts
their common global quantities, boundary and physical 1-D profiles to a
canonical `equilibrium` ODS and preserves all native output files. The explicit
COCOS number is retained in both the manifest and equilibrium code parameters.

The reference parameters are adapted from NICE's
`west_s53588_t35/param.xml` at the revision above. They select COCOS 11, the
standalone magnetic objective, an explicit VEST-sized computational contour,
and a scratch circular initialization. `prepare_nice_inputs` refuses to run
when the XML `inCOCOS`/`outCOCOS` values disagree with `NiceConfig`, or the
effective `useNewCOCOSManager=1` / `inoutCOCOS` setting is missing or inconsistent.
Standalone output is **not** in the configured input convention: the pinned
source explicitly leaves text tables in NCIpp. The collector restores COCOS 11
using the input current and toroidal-field signs, including the flux factor
`-sign(Ip)*2*pi` and its reciprocal for pressure/FF-prime derivatives.
Probe angles are passed unchanged; NICE performs its own angle conversion.

For the reference study, `diagnostic_source="equilibrium_constraints"` reads
the exact-time canonical constraint tree generated by the existing EFIT
conditioner. Raw and conditioned values, original uncertainties/enabled state,
conditioned uncertainties, weights, and both prescribed-response corrections
remain in the manifest. Positive weights enable magnetic channels; their
physical standard deviations determine the magnetic objective (matching EFIT's
`standard_deviation` mode). NICE prescribes Ip and active currents rather than
fitting EFIT's current constraints, so the complete objectives are not identical.

`correct_active_response=True` evaluates every original ODS winding-element
centroid and corrects the difference from the pinned NICE rectangle/filament
representation in the measurement equation, with fixed currents. This is an
observation-operator correction, not a change to the uncertainty or a claim
that the 93 native rectangles exactly reproduce the winding geometry everywhere.
Collection checks the actual native coil field at every enabled magnetic
diagnostic against the ODS response; errors must be below 0.1 sigma. The
reference's calibrated flux winding polarity is selected explicitly with
`flux_loop_input_sign=-1`. Generic cases retain the default polarity +1.

The VEST computational contour encloses the limiter and avoids both active
and passive conductors. Preparation rejects crossings, reversed orientation,
and incorrect node counts; collection rejects NICE boundary-node/edge mismatch
logs. Reduced VacTH families without both B-pol and flux loops are rejected
before launch: the pinned `VacTHSolver::DebugPlotData()` indexes `count-1`
unconditionally and crashes on an empty family. Diamagnetics remains explicitly
unsupported. The new-manager path also leaves `signBp/signF` uninitialized;
the collector rejects final diagnostic tables whose measured columns cannot
verify their sign against the manifest, records that as an auxiliary-output
warning, and does not reject an otherwise complete numerically converged
equilibrium. VacTH initializer residuals are preserved separately and never
presented as final-equilibrium residuals.

For issue #666's current stage, `scientifically_usable`/`ok` mean **numerical
stage success**: exit status zero, a finite valid equilibrium, a real (not
VacTH sentinel) convergence record, and final relative residual at or below
`epsStopRecon`. Diagnostic-table sign, residual quality, magnetic cost, Ip
agreement, and equilibrium comparison remain recorded quality evidence but do
not gate this status. A later physics-quality gate must assess those separately.

On Apple Silicon, the validated upstream regression build used AppleClang,
Eigen 3 and SuiteSparse in Release mode. Force-include `upstream_compat.h`
(and `cassert`) because this recorded NICE revision calls an unqualified
`legendre` and omits one assertion header. Eigen 5 is not compatible with the
pinned source. GCC 16 compiles it, but its bundled Triangle path did not finish
the reference reconstruction, so it is not the recorded validation compiler.

The issue #666 validation artifacts live in `validation/nice_issue_666`.
They intentionally retain failed slices: a zero exit status is not considered
a successful equilibrium unless NICE writes its native equilibrium and
convergence tables and does not report an invalid plasma.

Reproduce the corrected study using existing local clones and fresh output
directories (no network fetch or upstream source edits). `$NICEHOME` is the
built NICE source tree at the pinned revision; `--executable` names the
binary explicitly:

```sh
python -m vaft.code.nice.validate_reference \
  --nice-home "$NICEHOME" \
  --executable "$NICEHOME/build/nice_recon" \
  --efit-executable "$EFITHOME/bin/efit" \
  --efit-table-dir vaft/data/efit \
  --native-dir /path/to/fresh/native-run \
  --report-dir /path/to/fresh/report
```

The committed study predates develop's EFIT changes: the per-channel
decisions API (#296), EFIT-conformant sigma (#891), the regenerated Green
table (#701) and the 26-group coil set (#708). The conditioner now builds
the same channel set through the decisions API, but a re-run's EFIT side
will not reproduce the September numbers.

`--focus-only` runs 331 ms and its family study. `--collect-only` regenerates
`collected.json` from existing native artifacts after parser changes, preserving
the original run reports. JSON retains explicit NaN/Infinity failure evidence.
The reference windows have 9, 6, and 19 slices; no time is silently replaced
with a nearest neighbor. Exact-time EFIT inputs include an auxiliary 332 ms
slice because the shared conditioner requires a two-time grid.
