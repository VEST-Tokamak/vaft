# EFIT flux-loop channel selection: the evidence behind the manual list (issue #295)

The routine EFIT configuration
(`workflow/automatic_pipeline_1_routine_data_processing/config.yaml`,
`constraints.broken: [65, 66, 67, 68, 72, 74]`) zero-weights six flux loops on
every shot through a hand-maintained list that the constraint writer unions
with the automatic verdicts. Issue #295 asks that the list not survive as a
permanent automatic-plus-manual union: either the automatic evidence
reproduces each exclusion with a reason, or the exclusion is shown to be
unjustified and deleted.

This directory is **step 1** of that: the evidence table. It deletes nothing,
changes no weight, and writes nothing into any ODS.

## What the list actually names

The list is positional. The constraint writer converts it to zero-based and
numbers flux loops at `index + nbprobe`, where `nbprobe` is the number of
B-probes EFIT's geometry represents — **64** on VEST (`vaft.code.efit.kfile`).
So `65` is flux-loop index 0, whatever that loop is called. On the packaged
shots the mapping is:

The labels `FL01–FL04, FL08, FL10` that circulate for this list are positions
inside the flux-loop block, not loop names. The list excludes **all four
outboard loops (#3–#6)** and the two inboard loops at Z = ±0.696 m
(#12, #14). Physical Flux Loop #10 — the centre-column loop that doubles as
the loop-voltage channel for plasma-current compensation — is **kept**. Any
reasoning about the list that starts from "FL10 is the loop-voltage loop" is
reasoning about the wrong channel. Every row the script writes carries all
four identifiers so this cannot recur.

## Two classes of evidence, kept apart

`vaft.validation.flux_loop_assessment` combines, per loop:

- **source validity** — the magnetics signal-quality layer's verdict on the
  waveform itself (#189): the validity the diagnostics stage projected into
  the IDS (authoritative when present, re-assessed otherwise), the fraction
  of the assessment window it leaves usable, and the events behind it. This
  is the only evidence that rejects a loop on its own.
- **model agreement** — the loop's measured flux against the passive-wall
  forward model over the validated plasma-free interval of the #190
  benchmark (`run_benchmark_case`): improvement, normalised residual,
  correlation, wall authority. A disagreement is evidence about the model as
  much as about the loop (#253 §10), so by default it is **report-only**. A
  threshold in the policy marks a loop `suspect`; it rejects only when the
  policy says so explicitly *and* the wall term at that loop is large enough
  for the comparison to mean anything. It is never written back.

Every threshold is a `FluxLoopPolicy` field, echoed into each record. States
are `usable`, `suspect`, `reject_for_efit`, `not_available`.

## Running it

```bash
PYTHONPATH=. python workflow/efit_channel_selection/backtest_flux_loops.py \
    --packaged-samples --output flux_loops.json --markdown flux_loops.md
```

Each row is annotated against the manual list as `agree_reject`,
`agree_keep`, `false_rejection` (automatic rejects a loop the list keeps) or
`unreproduced_exclusion` (the list excludes a loop the evidence does not
reject). The exit status is 0 whatever the agreement: this is a report. The
#190 population lives in the VEST database, so the case list is an argument
(`--case SHOT=PATH`, repeatable); record the invocation with the output.
`--max-normalized-residual`, `--min-correlation`,
`--reject-on-model-disagreement` and `--min-wall-authority` set the policy;
`--no-benchmark` skips the model comparison.

## What the table says, and what it does not decide

- **The intrinsic layer reproduces none of the six exclusions.** Every loop
  on every packaged shot is fully usable inside the benchmark window; the
  only event is the `held_tail` after the diagnostics window on 39915 and
  41524, which is outside it. Whatever put these loops on the list, it was
  not a waveform defect the quality layer can see on these shots.
- **On 39915 the excluded loops are the ones that agree *best* with the wall
  model** (improvement 0.97–0.98, normalised residual ≤ 0.03), and the one
  loop the model does not explain — physical #10, improvement −0.22 — is one
  the list keeps. On 41672 the picture is similar but weaker (improvement
  0.72–0.89 for the excluded outboard loops, 0.40 for #14).
- **41524 is not a usable model witness.** Its `coil_drive` block reports a
  window peak coil current 0.003 of the shot peak, below the 0.1 floor: the
  residuals there are ratios of noise, and the table records that rather
  than hiding it.
- With a model threshold (`--max-normalized-residual 0.5`) the loops that
  turn `suspect` are #10 on 39915; #4, #5, #10, #13 on 41672; and every loop
  on the undriven 41524. None of those sets is the manual set, and on the
  two driven shots the six excluded loops are all below the threshold except
  #4 and #5 on 41672. That is a statement about the plasma-free forward model
  at those loops, not a verdict on the loops.

Step 1 therefore does **not** license deleting the list: three packaged
shots are not the #190 population, and the historical reason for the
exclusions (plasma-phase behaviour, a calibration era, an EFIT weighting
decision) is not something a plasma-free benchmark can see. What it does
establish is that the six loops are not broken in the sense the automatic
policy can detect, so the next step is to find the reason the list was
written — or to run this table over the database population with the
plasma-phase EFIT residuals beside it — before #295 §4 removes anything.
