Scientific contracts

At a glance

Architecture position
Where VAFT's scientific contracts are defined: quantity identity, units, COCOS and machine polarity, Fourier conventions, applicability, validation evidence and provenance. Records who owns each, how it is enforced, and the gaps the interoperability work of #2160 closes (audit of #2161).
Prerequisites / inputs
The Scientific architecture and Credibility and applicability pages.
Expected result
Which module is authoritative for a definition, a transformation and a verdict; which conventions are machine-readable and which are prose only; and why VAFT extends its existing taxonomy instead of adding a quantity registry.
Status
Maintained against the pinned develop baseline.

VAFT already defines most of its scientific contracts. They live in the modules that own the science, though, and nothing connects them. This page is the audit behind the Scientific Contracts initiative (#2160, Phase A #2161). It inventories the contracts, names an owner for each one, traces five representative paths end to end, and records the minimal work Phase B (#2163) has to do.

It audits develop at 7b1fcf192. Symbols are cited by name so that line drift does not break the references. When this page and an owning module disagree, the module wins, and the disagreement is a documentation bug.

Four questions kept apart

The audit keeps four questions separate because the code already does, and merging them was the main risk the initiative identified:

Question Answered by Never answered by
Do two values mean the same physical thing? quantity identity: vaft.plot.taxonomy, vaft.formula.boundaries matching units or dimensions
Is this representation the one it claims to be? convention checks: vaft.validation.cocos, vaft.validation.perturbation_phase a declaration alone
Do the model’s assumptions hold here? vaft.validation.applicability with vaft.validation.orderings solver convergence
Is the result supported by evidence? vaft.validation.credibility, six axes (E/T/I/A/N/V) any single score

Inventory and coverage

Coverage labels describe the software (existing, partial, missing, unresolved). They are not physical applicability verdicts. Enforcement is one of: doc (prose only), structural (checked when docs or catalogs are generated), runtime (checked when called) or independent (checked against data the result did not use).

Out of scope, with owners recorded: the unresolved VEST polarity (#288); collisionality and gyroradius definition consolidation (#353); expansion of applicability contracts (#1627, #1628); consolidating the COCOS transform paths, and COCOS checks at the GPEC, EFIT and TES boundaries (follow-ups to be filed after Phase B).

Five traces

Each step is marked reliable (machine-checked), implicit (correct, but resting on caller knowledge or prose), verifiable (an independent check exists and can be run), or gap (Phase B work).

A. COCOS through an equilibrium chain

  1. A g-file or ODS enters. equilibrium_psi_to_weber reads the declared COCOS, or probes Wb against Wb/rad through flux_exponent_tier (slope, Ampère, contour q), and refuses when no tier decides. Verifiable. The separate reader-side ods_psi_to_wb_per_radian_factor runs the same probes but ends in a stated default of 1/(2π), which is implicit.
  2. _resolve_convention builds EquilibriumConvention: identification always runs and the declaration wins, with contradicted set when they disagree. Reliable, but the evidence level lives in booleans and the source string. Gap: no shared evidence vocabulary.
  3. convert_cocos applies omas factors to ψ, F, q, p′, FF′, I_p and B0, and refuses an ambiguous source. Reliable. What it keeps is a free-text source (“converted from COCOS N”) plus the carried identified candidates, not a structured record. Gap for Phase C.
  4. CHEASE input forces signs to COCOS 2 with CHEASE_ORIENTATION. Reliable (byte parity test).
  5. The GPEC g-file copy (copy_gfile_for_gpec) passes the file through without a COCOS check. Gap, filed as a follow-up and kept out of this initiative.
  6. VEST machine polarity (IP_SIGN_VEST_TO_IMAS.confirmed=False) never enters steps 1–5. Unresolved, owned by #288. Correct COCOS handling of the stored data does not confirm it.

B. Greenwald density in engineering units

  1. greenwald_density(I_p, a) takes I_p [MA] and returns [1e19 m^-3]. Its Convention section notes that the literature quotes 10²⁰. Implicit: the unit is a docstring tag.
  2. Callers convert by hand: _synthetic_kinetic_profiles writes 1e19 * greenwald_density(abs(ip)/1e6, …), and plot.history sniffs column names (Ip_MA, ne_19m3). Implicit.
  3. greenwald_fraction(n_e, n_G) expects a line-averaged density in the same unit, stated only in prose. Implicit.
  4. Nothing can detect a caller passing amperes. The result would be 10⁶ too large, finite and silent. Gap: no parsed unit, no opt-in assessment.
  5. Normalized beta follows the same pattern three times: beta_N_from_beta_a_B0_Ip (% and MA), beta_normal_from_beta_tor (fraction and A, converted inside), beta_normal_from_beta_volume (Menard ⟨β_N⟩, a different beta in the same unit). Gap: the taxonomy has a single beta_n.

C. Complex toroidal response

  1. Sector currents I_k = A cos(nφ_k + δ) come from phased_sector_currents. Reliable.
  2. toroidal_mode_decomposition gives C_n = (A/2) e^{+iδ} with kernel e^{-inφ} and 1/K. Reliable (test_cosine_pattern_gives_half_amplitude_and_positive_phase), but the convention is prose. Gap.
  3. GPEC writes fields under Re(C e^{-inφ}). toroidal_phase_audit compares the stored coefficient and its conjugate against a Biot–Savart reference. Verifiable, with a gauge-invariant separation ratio.
  4. phase_convention_verdict returns PASS or INDETERMINATE. Reliable when called, but nothing calls it. Gap for Phase C.
  5. The VEST coil-direction words are an open conflict (VEST_GPEC_COIL_DIRECTIONS). Unresolved.

D. Model applicability

  1. A state (dict, DataFrame row or object) holds ordering quantities named as in ORDERING_QUANTITIES. Reliable.
  2. evaluate_contract(CONTRACTS["gyrokinetic_delta_f"], state) returns per-assumption margins (log10 of threshold over value) and SUPPORTED, OUTSIDE, UNASSESSED or NOT_APPLICABLE. A missing input gives UNASSESSED, never SUPPORTED. Reliable.
  3. as_evidence places the result on the A axis. compose keeps it apart from N. Reliable.
  4. Adapters record ordering_provenance in run provenance as advisory data. This is explicit and never automatic. Reliable. No gap for this initiative beyond attaching the evaluation to a result context (Phase C).

E. Two densities with the same unit

  1. formula.boundaries separates line_average_density from edge_density, whose definition says it is “not the line-averaged or separatrix density”. Reliable inside boundaries. No separatrix density is defined anywhere as a quantity of its own.
  2. The taxonomy has only the subject electron_density (ne, n_e); it is not a canonical quantity. Both densities would resolve to that subject. Gap.
  3. The ontology never ingests boundaries, so the distinction is invisible there. Gap for Phase D.
  4. Nothing anywhere treats these as interchangeable, but nothing would stop it. Gap: no compatibility check that refuses it.

Phase B specification

Each item names its gap, owner, behaviour, tests and constraints. Everything is opt-in: no formula signature, return type or import cost changes.

  1. Unit scale (vaft.formula.units, new).
    • Gap: unparsed unit tags and about 15 hand-written conversions.
    • Behaviour: parse_unit covers only the tags the audit found in use (A, kA, MA, W, kW, MW, T, G, J, eV, keV, m, m⁻³, 10¹⁹ m⁻³, 10²⁰ m⁻³, s, ms, Wb, -, %). conversion_factor refuses a dimension mismatch and refuses Wb/rad, pointing to the COCOS provider instead. An unknown tag raises; nothing is guessed.
    • Tests: the scale factors; refusals; an unknown tag; no numpy-free import cost.
  2. Identity distinctions (vaft.plot.taxonomy, vaft.formula.boundaries).
    • Gap: density averaging, ψ vs ψ_N, vacuum vs response field; two disjoint identity vocabularies.
    • Behaviour: add canonical quantities for those distinctions without merging aliases. Add an optional BoundaryQuantity.concept resolved through resolve_quantity. same_quantity keeps its meaning. A separate predicate reports when the same quantity is held in two convertible units.
    • Tests: no alias collisions; every boundary concept resolves; the 10¹⁹ and 10²⁰ line densities are convertible but same_quantity is still false.
  3. Fourier descriptor (vaft.data.fourier, new).
    • Gap: kernels are prose only.
    • Behaviour: a frozen FourierConvention (kernel sign, normalization, sidedness, angle orientation, phase origin) with named constants for the four kernels above, each citing its function. An explicit coefficient conversion is allowed only for coefficients of a real field with every field declared. A differing phase origin or orientation is never bridged.
    • Tests: the sector-current → decomposition → GPEC-convention round trip reproduces the toroidal_phase_audit coefficient and the real-space field; missing metadata raises.
  4. Representation and compatibility (vaft.data.representation, new).
    • Gap: no common way to ask whether two representations can be combined.
    • Behaviour: a Representation (quantity, unit, optional COCOS and Fourier convention, evidence level: declared, inferred, verified or unresolved) and assess_compatibility with outcomes COMPATIBLE, REQUIRES_TRANSFORM, INCOMPATIBLE and UNRESOLVED, structured reasons, and a reference to the transformation provider. These outcomes are not validation statuses. Assessment never touches arrays; executing a transform is a separate call. EquilibriumConvention maps to a representation, with contradicted or ambiguous giving UNRESOLVED.
    • Tests: Cases A, B, C and E; a family match is INCOMPATIBLE; missing units or COCOS give UNRESOLVED; inputs are not mutated.
  5. Opt-in boundary (vaft.formula.catalog).
    • Behaviour: derive a parameter’s Representation from its existing unit tag and Semantics term, so a caller can assess before calling greenwald_density or a β_N function.
    • Tests: the Greenwald I_p parameter is MA; a value in A is REQUIRES_TRANSFORM with factor 10⁻⁶; a value with no unit is UNRESOLVED.

Phase C (#2165) then adds a transformation record, the first producers of transformation (T) evidence, and an opt-in result context. Phase D (#2167) exposes all of it through the generated catalogs and ontology.
